☁ Tuya Cloud (API)

Poświadczenia projektu Tuya IoT (developer.tuya.com) - potrzebne do importu urządzeń z konta Tuya, ich sterowania przez chmurę i detekcji ruchu z kamer Tuya. Urządzenia z kompletem danych (adres IP + local_key) trafiają do sterowania lokalnego (zakładka 🔌 Tuya (LAN) - szybsze, nie wymaga internetu); reszta ląduje niżej jako sterowana przez chmurę - lokalne ma zawsze pierwszeństwo, jeśli to samo urządzenie skonfigurujesz też tam. Wymagane zalogowanie administratora panelu - dotyczy zarówno przeglądania tej strony, jak i zapisu.

⚙ Ustawienia wtyczki

Włącz/wyłącz tę integrację i ustaw poziom logowania jej zdarzeń (niezależnie od domyślnego poziomu globalnego - zakładka ⚙ Ustawienia ogólne). Wyłączenie/włączenie wymaga pełnego restartu procesu bridge'a, poziom logowania działa od razu, bez restartu.

Poświadczenia API

Access ID/Secret z panelu developer.tuya.com (projekt Cloud, region zgodny z aplikacją Tuya/Smart Life). Access Secret nigdy nie wraca do przeglądarki po zapisie - puste pole przy zapisie oznacza "zostaw bez zmian".

Zakresy/adresy IP do skanowania

Broadcast UDP (wykorzystywany przez skan LAN w zakładce 🔌 Tuya (LAN)) nie zawsze dociera do bridge'a (kontener Docker bez trybu network: host, VLAN-y, bridge w innej podsieci niż urządzenia) - podaj tu adresy IP i/albo zakresy CIDR do aktywnego przeskanowania (np. 192.168.1.0/24 albo pojedynczy adres 192.168.1.50). Dotyczy to WYŁĄCZNIE urządzeń, których ID+local_key już znamy (skonfigurowanych w zakładce 🔌 Tuya (LAN) albo poniższym importem) - import niżej i "Rescan" wykorzystują te same zakresy do aktywnego sprawdzenia adresu IP. Te same zakresy widać i da się je edytować też w zakładce 🔌 Tuya (LAN) - to jedno wspólne ustawienie używane przez obie strony.

Import urządzeń

Pobiera WSZYSTKIE urządzenia podpięte do projektu Tuya Cloud, używając poświadczeń zapisanych wyżej (zapisz je najpierw) - jeśli w sekcji "Zakresy/adresy IP do skanowania" wyżej podałeś adresy, import od razu aktywnie sprawdza te adresy (nie tylko broadcast), więc może znaleźć komplet danych (adres IP + local_key) nawet gdy broadcast nie działa. Urządzenia z kompletem danych pojawiają się niżej z przyciskiem "➡ Dodaj jako lokalne" (🟢 nowe, 🟠 już skonfigurowane lokalnie) - reszta ląduje w tabeli "Urządzenia sterowane przez chmurę" (też oznaczona 🟢/🟠).

Urządzenia sterowane przez chmurę

Urządzenia BEZ local_key/adresu IP (Tuya Cloud ich nie zwróciła, albo urządzenie nie jest w tej samej sieci LAN) - sterowane przez Tuya Cloud (REST), wolniej i zależnie od internetu. "Kod przełącznika" to kod DP wysyłany przy włączaniu/wyłączaniu - switch_1 pasuje do większości gniazdek/przełączników, zmień go, jeśli sterowanie nie działa (sprawdź kod w zakładce "Cloud Debugging" na developer.tuya.com).
Urządzenia inne niż zwykły włącznik (czujniki, liczniki, sterowniki nawadniania...) pokazują tylko surowe numery pól, dopóki nie pobierzesz ich opisu - wymaga zapisanych poświadczeń wyżej.
Urządzenie sterowane przez chmurę może z czasem znaleźć się w tej samej sieci LAN co bridge (np. po zmianie routera/WiFi) - "Rescan" ponownie sprawdza zapisane niżej urządzenia (skan LAN + Tuya Cloud) i pokazuje, które z nich da się teraz przenieść na szybsze sterowanie lokalne (wymaga zapisanych poświadczeń Tuya Cloud wyżej i zapisanych urządzeń niżej).
